# 超时 HUD 的真实 UIKit 回归

在带 Xcode 的 Mac，从仓库根目录运行：

```sh
make -C dm/host/tests build/t_rift_overtime build/t_rift_clock
dm/host/tests/build/t_rift_overtime
dm/host/tests/build/t_rift_clock
zsh dm/ios/tests/rift_overtime_catalyst/run.sh
```

执行生产 dm_rift.c 数据生产函数、dm_rift_hud.m 原有绘制设施、生产自主串表及真实 Mac Catalyst UIKit 图层。中英各五种状态：进行中899秒、900秒尚无守护者、930秒守护者已出现、超时打倒守护者、限时内打倒守护者。脚本动态发现限定Xcode SDK，使用临时产物/系统字体回退，不改模拟器状态。PNG及结果仅本地生成、不提交。无游戏内容。

修改前10案例共8个断言失败（中英各两个进行中超时案例缺少状态/规则文字）；修改后10案例零失败。已打开中英守护者超时PNG，文字可读。这是真实UIKit离屏结果，不是原生游戏或iPad测试。宿主测试覆盖边界/长时间超时/未开场/闲置、读数不改变状态、既有继续/放弃请求；真实客体时钟冻结测试仍6/6通过。

维护方原生验收：

1. 中英、11/13寸iPad，在守护者出现前/战斗中跨过15分钟。持续显示超时及规则、0:00，进度/守护者状态继续有效。不强制回城/清怪/结算，不偷偷重启计时。
2. 继续攒进度/击杀守护者。沿用普通原生掉落，不得计限时通关/解锁/首通奖励；结算与战利品返回沿用现有逻辑。实际掉落须游戏验证，宿主/UI不能证明。
3. 使用现有回城卷轴/免费回城操作，打开城镇秘境菜单。显示超时标题、继续拾取说明及继续/放弃规则。继续保留场次/位置，放弃沿用已有确认/长按语义。这笔不新增自动回城门或图内直接放弃动作。
4. 限时完成、超时完成仍显示各自状态；后台/锁屏客体时间冻结。标签不截断，不新增焦点拦截。
5. 与PR31一起采纳时保留其next_tier封顶/奖励队列/旧场安全保护，合并overtime字段与分支，不拿任一PR整文件覆盖另一笔。#29的103显示独立跟踪。

完整原生构建/重写/图形/启动/真机验收需要合法自备3.3.94012资源，此处未运行；通过前保留草稿。参考暴雪2.3.0仅限时完成可升级宝石、2.7.3单人可主动关闭未结束大米。这笔说明现有项目规则，不引入新的D3奖励系统。
